This chapter presents the concepts used to formulate and solve the problem
studied in this thesis. It first introduces combinatorial optimization, then
explains the main solution approaches, and finally describes the routing
problems from which MPVRP-CC draws its characteristics. The $n$-queens problem
provides a running example for distinguishing a problem, its model, and the
procedure used to solve it.

\section{Combinatorial optimization}

\subsection{Basic concepts}

An optimization problem asks us to choose the best feasible decision according
to a specified criterion. In combinatorial optimization, the decisions involve
discrete choices, such as assigning tasks, selecting objects, or ordering visits.
The number of possible combinations can grow rapidly with the instance size.

The following vocabulary is used throughout the chapter. The constraint-based
view follows the terminology presented in the handbook edited by
Rossi, van Beek, and Walsh~\cite{rossi2006handbook}.

\begin{description}
\item[Variable.] A decision variable represents an unknown quantity whose value
must be determined. Write $X=(x_1,\ldots,x_n)$ for the collection of variables.
The value of a variable can represent a vehicle assignment, a quantity, or a
position in an ordering.

\item[Domain.] The domain $D(x_i)$ is the set of values allowed for $x_i$.
Depending on its domain, a variable may be:
\begin{itemize}
 \item binary: $D(x_i)=\{0,1\}$;
 \item integer: $D(x_i)\subseteq\mathbb{Z}$, or
       $D(x_i)\subseteq\mathbb{N}$ when only nonnegative values are allowed;
 \item continuous: $D(x_i)\subseteq\mathbb{R}$.
\end{itemize}
Finite-domain combinatorial models use discrete variables. Continuous variables
may also appear in mixed models, for example to represent delivered quantities.

\item[Constraint.] A constraint specifies which combinations of values are
allowed. For example, $x_1\neq x_2$ forbids two variables from taking the same
value, while $x_1+x_2\leq Q$ imposes an upper limit on their sum. Let $C$ denote
the set of constraints.

\item[Assignment.] A complete assignment $a=(a_1,\ldots,a_n)$ selects one value
$a_i\in D(x_i)$ for every variable. A partial assignment fixes only some values.

\item[Feasible solution.] A complete assignment is feasible if it satisfies
all constraints. The feasible set is
\[
 F=\left\{a\in\prod_{i=1}^{n}D(x_i): c(a)\text{ holds for every }c\in C\right\}.
\]
If $F=\varnothing$, the problem instance is infeasible.

\item[Objective function.] An objective $f$ associates a numerical value with
each feasible solution. It expresses the criterion to minimize or maximize,
such as total cost, travel distance, or service quality.

\item[Optimal solution.] For a minimization problem, $a^\star$ is optimal when
\[
 a^\star\in F\quad\text{and}\quad
 f(a^\star)\leq f(a)\qquad\text{for every }a\in F.
\]
Several solutions can attain the same optimal value. Feasibility alone does
not imply optimality.
\end{description}

\subsection{Satisfaction and optimization problems}

A \emph{constraint satisfaction problem} (CSP) is described by $(X,D,C)$:
variables, their domains, and constraints. Its goal is to find an element of
$F$, or establish that none exists. There is no objective ranking feasible
solutions.

A \emph{constraint optimization problem} (COP) adds an objective and its
direction. In the minimization case, it can be written as
\[
 \min_{a\in F} f(a).
\]
Thus, a CSP asks ``Can these requirements be satisfied?'', whereas a COP asks
``Which feasible solution has the best objective value?'' The same application
may be studied in either form, depending on the question being asked.

\subsection{Example: the $n$-queens problem}

The $n$-queens problem consists of placing $n$ queens on an $n\times n$
chessboard so that no two queens attack each other. Queens must not share a
row, a column, or a diagonal. It is naturally a satisfaction problem: any
non-attacking arrangement is acceptable.

Place one queen in each column and let $q_i$ denote its row in column $i$.
Then $D(q_i)=\{1,\ldots,n\}$. For every $i<j$, the requirements are
\[
 q_i\neq q_j,
 \qquad |q_i-q_j|\neq |i-j|.
\]
The first condition prevents shared rows; the second prevents shared diagonals.
Having one variable per column already enforces the column requirement.
For $n=4$, the assignment $(q_1,q_2,q_3,q_4)=(2,4,1,3)$ is feasible.

\subsection{Computational complexity}

Complexity describes how the resources needed by an algorithm grow with the
size of its input. The classes below concern \emph{decision problems}, whose
answer is yes or no~\cite{cornell2015complexity}.

\begin{description}
\item[P.] Problems solvable in polynomial time by a deterministic algorithm.
\item[NP.] Problems for which a yes-answer has a certificate verifiable in
polynomial time. NP does not mean ``non-polynomial''.
\item[NP-hard.] A problem is NP-hard if every problem in NP can be reduced
to it in polynomial time. It need not itself belong to NP.
\item[NP-complete.] A decision problem that is both in NP and NP-hard.
\end{description}

We know that $\mathrm{P}\subseteq\mathrm{NP}$; whether these classes are equal
remains unresolved. NP-hardness does not mean that every instance is difficult.

An optimization problem can be associated with a decision question: ``Does a
feasible solution of cost at most $B$ exist?'' This distinction matters when
classifying routing problems: the optimization TSP is NP-hard, while its
standard decision version is NP-complete. The ordinary $n$-queens example is
used here to explain modeling, not as evidence of NP-hardness.

\subsection{From a problem to a solver}

Solving an application requires several steps:
\begin{enumerate}
 \item \textbf{Problem:} identify the practical situation and the planning need.
 \item \textbf{Problem definition:} specify the data, decisions, assumptions,
 constraints, and objective.
 \item \textbf{Models:} translate this definition into mathematical objects,
 for example a MILP model or a CP model.
 \item \textbf{General-purpose solver:} implement the selected model in a
 compatible solver and configure its search and stopping criteria.
\end{enumerate}

A solver operates on the model it receives. Consequently, a mathematically
optimal result is useful only if the model correctly represents the intended
problem. Returned solutions must also be checked against the problem definition.

\section{Solution methods}

The following approaches offer different ways to explore a solution space.
They can also be combined: a MILP solver may use heuristics, while a CP solver
may use heuristic rules to order a systematic search.

\subsection{Heuristics and metaheuristics}

\textbf{Heuristic.} A heuristic is a rule or procedure intended to find useful
solutions with limited computational effort, without generally guaranteeing
an optimal solution. A construction heuristic builds a solution progressively;
an improvement heuristic modifies an existing solution.

\textbf{Nearest neighbor.} Starting from a location $i$, select the closest
unvisited eligible location:
\[
 j\in\arg\min_{v\in U_i}c_{iv},
\]
where $U_i$ contains the currently eligible candidates. Repeat until the tour
is complete. This rule is simple, but an attractive immediate move can leave
an expensive final connection. With additional routing constraints, it can
also lead to a dead end.

\textbf{2-opt.} In a symmetric tour, remove two non-adjacent edges and reconnect
the resulting segments by reversing the intervening segment. Replacing
$(a,b)$ and $(c,d)$ with $(a,c)$ and $(b,d)$ improves the cost when
\[
 c_{ac}+c_{bd}<c_{ab}+c_{cd}.
\]
Feasibility must still be checked. For asymmetric costs, the costs of all
reversed internal arcs also matter. Figure~\ref{fig:two-opt} illustrates the
same reconnection on an open path; its endpoints remain fixed.

\textbf{Metaheuristic.} A metaheuristic is a broader search strategy organizing
heuristic decisions and exploration. Examples include tabu search, simulated
annealing, genetic algorithms, and large neighborhood search. Such strategies
help explore beyond the solutions reached by a single greedy rule or local
improvement procedure~\cite{laporte2000heuristics,shaw1998constraint}.

\textbf{A simple four-queens heuristic.} Process columns from left to right
and choose the smallest row that does not conflict with an already placed
queen. This gives $q_1=1$, then $q_2=3$. No row is then available for column
3, so the procedure stops without a solution, although a solution exists.

This example separates failure of a heuristic from infeasibility of a problem.
A restart can try different choices. Alternatively, systematic backtracking
can revisit earlier decisions and explore the remaining alternatives.

\subsection{Linear and mixed-integer programming}

\textbf{Linear programming.} A linear program (LP) has a linear objective,
linear constraints, and continuous variables. One standard form is
\begin{align*}
 \min\quad & c^\top x\\
 \text{subject to}\quad & Ax\leq b,\\
 & x\geq 0,
\end{align*}
where $x\in\mathbb{R}^n$ is the decision vector, $c$ contains objective
coefficients, and $A$ and $b$ encode constraints. Equalities and other variable
bounds can also be included.

\textbf{Mixed-integer linear programming.} A MILP additionally requires
$x_i\in\mathbb{Z}$ for selected indices $i\in I$. Binary variables are integer
variables restricted to $\{0,1\}$. They can represent choices such as using a
vehicle or traversing an arc. Continuous variables can represent quantities.
The objective and constraints remain linear.

\textbf{Relaxation.} The LP relaxation removes integrality requirements.
Its feasible set contains that of the MILP, so for minimization its optimal
value is a lower bound on the integer optimum. For example,
\[
 \min x\quad\text{subject to }2x\geq3,\quad x\geq0,\quad x\in\mathbb{Z}
\]
has optimum $x=2$, whereas its LP relaxation has optimum $x=1.5$.

\textbf{Branch-and-bound.} The solver divides the problem into subproblems.
If a relaxed solution has $x_i=2.4$, for example, it may create the branches
$x_i\leq2$ and $x_i\geq3$. Relaxations provide lower bounds; feasible integer
solutions provide upper bounds. A branch is discarded when it is infeasible
or its bound shows that it cannot improve the best solution found.

\textbf{Branch-and-cut.} This extends branch-and-bound by adding valid
inequalities, called cuts, which exclude unwanted fractional solutions
without removing feasible integer solutions. These techniques underlie
modern MILP solvers~\cite{gurobiMipBasics,gurobiDocs}.

A solver stopped by a time limit may return a feasible incumbent without
proving optimality. For minimization, valid bounds satisfy
$LB\leq z^\star\leq UB$; they must be reported alongside the solution status.

\subsection{Constraint programming}

\textbf{Paradigm.} Constraint programming (CP) expresses a problem using
variables, domains, and relations that must hold between their values. It
supports both satisfaction and optimization. In finite-domain CP, propagation
and search cooperate to reduce and explore the candidate assignments
\cite{rossi2006handbook}.

\subsubsection{Types of constraints}

\begin{description}
\item[Arithmetic constraints.] These relate numerical expressions, such as
$x+y\leq Q$, $x\neq y$, or $|q_i-q_j|\neq|i-j|$.
\item[Logical constraints.] These express combinations or implications, such
as $b=1\Rightarrow x\leq Q$, where $b$ is binary. Reification links a Boolean
variable to the truth of a constraint, for example $b\Leftrightarrow(x<y)$.
\item[Global constraints.] These describe a structured relation over a group
of variables. For example, $\operatorname{AllDifferent}(x_1,\ldots,x_n)$
requires pairwise distinct values; $\operatorname{Circuit}$ describes a tour;
and cumulative constraints limit simultaneous resource use. A dedicated
propagator can exploit the structure of the entire relation.
\end{description}

\subsubsection{Filtering, propagation, and inconsistency}

\textbf{Filtering.} A filtering algorithm removes domain values that cannot
participate in a solution of the constraint under the current domains.
Correct filtering preserves every feasible completion. Its strength depends
on the consistency level enforced; it need not detect every impossible value.

\textbf{Propagation.} When a domain changes, affected constraints apply their
filtering algorithms. This process repeats until no further reduction is
obtained, or a failure is detected. For instance, if
$D(x)=D(y)=\{1,2\}$ and $x<y$, propagation yields
$D(x)=\{1\}$ and $D(y)=\{2\}$.

\textbf{Inconsistency.} A current search state is inconsistent when no complete
assignment extending it satisfies all constraints. An empty domain is a clear
sign of failure. However, nonempty domains after propagation do not necessarily
prove that a feasible completion exists.

\subsubsection{Systematic search and branching}

If propagation does not determine a complete solution, the solver makes a
branching decision. A common binary split is
\[
 x=v \qquad\text{or}\qquad x\neq v.
\]
Each branch triggers propagation. On failure, the solver backtracks and tries
another alternative. Exhaustively exploring a finite search space can prove
infeasibility or optimality, provided the search is complete and is not stopped
early.

Branching has two main choices:
\begin{itemize}
 \item \textbf{Variable selection:} choose the next variable, for example the
 one with the smallest non-singleton domain (the first-fail rule).
 \item \textbf{Value selection:} choose which value or domain part to explore
 first, for example the smallest value or a value expected to leave more
 possibilities for other variables.
\end{itemize}

These heuristic choices determine the exploration order. They do not make an
otherwise exhaustive search incomplete. For a COP, objective bounds can also
remove branches that cannot improve the incumbent.

\subsubsection{A CP model for $n$-queens}

The earlier definition translates into a compact model:
\begin{align*}
 &q_i\in\{1,\ldots,n\} && i=1,\ldots,n,\\
 &\operatorname{AllDifferent}(q_1,\ldots,q_n),\\
 &\operatorname{AllDifferent}(q_1-1,q_2-2,\ldots,q_n-n),\\
 &\operatorname{AllDifferent}(q_1+1,q_2+2,\ldots,q_n+n).
\end{align*}
The first global constraint prevents shared rows. The other two prevent shared
diagonals because squares on the same diagonal have the same row-minus-column
or row-plus-column value. These expressions can be represented by auxiliary
variables or views, depending on the solver. No objective is required.

For four queens, setting $q_1=2$ removes rows 1, 2, and 3 from $D(q_2)$,
leaving $q_2=4$. Further propagation gives $q_3=1$ and $q_4=3$.
This illustrates how the model communicates consequences between decisions.

\subsubsection{Successor variables}

In a routing model, a successor variable $s_i$ identifies the node visited
immediately after node $i$. Its domain contains the permitted successors.
For a tour on $V$, the assignments $s_1=3$, $s_3=2$, and $s_2=1$ represent
$1\rightarrow3\rightarrow2\rightarrow1$.

Requiring distinct successors alone can produce several disjoint cycles.
A circuit constraint additionally enforces the required single cycle.
Multiple routes and optional visits require appropriate extensions of this
representation~\cite{vismara2018circuit}. The interpretation of self-loops and
depot copies must therefore be stated by the particular model.

\subsection{Sequence variables}

Delecluse et al.~\cite{delecluse2025sequence} formalize a domain whose values
are sequences of distinct nodes. Fixed start and end nodes delimit a route.
The domain combines a partial sequence, required and excluded nodes, and
restrictions on insertion positions.

A required node must occur in every completion but need not yet be placed.
An optional node may still be included or excluded. Insertion preserves the
relative order of already placed nodes; it does not permanently fix their
adjacency.

For example, inserting $r$ into $\langle s,a,b,t\rangle$ can yield
$\langle s,a,r,b,t\rangle$. The domain supports insertion, requiring a node,
excluding a node, and forbidding its occurrence between specified nodes.
Search branches on such choices, while constraints filter the domain.
Distance, transition-time, precedence, and cumulative constraints connect
sequences to routing requirements. A fixed variable represents one complete
sequence, with membership decisions resolved. This representation supports
optional visits and insertion-based search directly.

\section{Routing problems}\label{sec:routing-background}

\subsection{From the TSP to the VRP}

The traveling salesman problem (TSP) asks for a minimum-cost tour visiting
each required location once and returning to its origin. Dantzig, Fulkerson,
and Johnson's 1954 study is a foundational contribution to its mathematical
solution~\cite{dantzig1954tsp}. Dantzig and Ramser subsequently studied truck
routing with delivery requirements and vehicle capacity~\cite{dantzig1959truck},
a foundational formulation of the vehicle routing problem (VRP).

The VRP adds fleet assignment to visit ordering: the planner decides both
which vehicle serves a customer and in which order its visits occur.
The notation below will support the variant descriptions
\cite{toth2014vehicle}.

\begin{description}
 \item[$G=(V,A)$.] A directed graph, with locations $V$ and permitted arcs $A$.
 \item[$N$ and $D$.] Customer and depot sets, with $V=N\cup D$.
 \item[$K$.] The set of available vehicles.
 \item[$c_{ij}$.] Travel cost on arc $(i,j)\in A$.
 \item[$d_i$ and $Q_k$.] Customer demand and vehicle capacity, respectively.
\end{description}

Costs may be symmetric ($c_{ij}=c_{ji}$) or asymmetric. The cost of a tour
$\pi=(v_0,v_1,\ldots,v_m,v_0)$ is
\[
 C(\pi)=\sum_{j=0}^{m-1}c_{v_jv_{j+1}}+c_{v_mv_0}.
\]
For several vehicles, travel cost is summed over their routes. Other terms,
such as vehicle-use costs or changeover costs, can be included in the objective.

\textbf{Fleet types.} A homogeneous fleet has identical relevant vehicle
characteristics. A heterogeneous fleet may have different capacities,
operating costs, or product compatibilities. A fixed-fleet problem specifies
the available vehicles; fleet-size or fleet-composition variants additionally
decide how many vehicles, or which types, to use.

\subsection{Capacitated vehicle routing}

The capacitated VRP limits the load carried by each vehicle. In the basic
single-depot delivery setting, every customer is served once and every route
starts and ends at the depot. If vehicle $k$ loads all deliveries at departure
and serves customers $N_k$, feasibility requires
\[
 \sum_{i\in N_k}d_i\leq Q_k.
\]
This expression applies to one delivery load. With reloading or pickups,
capacity must instead be respected as the load evolves.

\subsection{Vehicle routing with multiple trips}

A multi-trip VRP allows a vehicle to perform several trips within the planning
horizon~\cite{cattaruzza2016multipletrips}. After completing a delivery trip,
a vehicle can return to a loading facility and depart with another load.
The number of trips can therefore exceed the number of vehicles.

In this chapter, a trip denotes one loading-and-delivery cycle, while a vehicle
route denotes its complete ordered plan. Trip assignment and trip succession
both matter when the same vehicle is reused. Figure~\ref{fig:multiple-trips}
shows a conventional single-depot example; more general settings can allow
several loading facilities.

\subsection{Multi-product and multi-commodity routing}

Multi-product routing distinguishes product types. Let $P$ be the product set
and $d_{ip}$ the demand for product $p$ at customer $i$. Vehicles must satisfy
these demands while respecting the relevant loading and compatibility rules.
A vehicle may carry one product per trip, several products together, or
separated products in compartments, depending on the application.

The term multi-commodity also distinguishes flows, potentially by product,
origin, or destination. It does not by itself specify whether goods can mix.
These assumptions must be stated explicitly. Product-dependent preparation
makes the order of loads important: a transition from $p$ to $p'$ may incur
$h_{pp'}$, with no requirement that $h_{pp'}=h_{p'p}$.

\subsection{Split deliveries and depot-related routing}

\textbf{Split deliveries.} A customer's demand may be fulfilled through
several visits or vehicles. If $y_{ikp}$ is the total quantity of product $p$
delivered to customer $i$ by vehicle $k$, demand satisfaction can be expressed
as $\sum_{k\in K}y_{ikp}=d_{ip}$. Allowing a split changes the assignment
structure compared with serving each demand in one visit.

\textbf{Depots and available stock.} Multiple-depot settings add decisions
about loading locations or vehicle bases. If depot $d$ holds $S_{dp}$ units
of product $p$, total withdrawals of that product cannot exceed $S_{dp}$.
These stock constraints couple routes through a shared resource.

\textbf{Inventory routing.} Inventory-routing problems jointly plan routing
and replenishment over time, usually tracking inventory levels across periods.
A single-period problem with limited depot stocks has an inventory-related
constraint, but is not automatically a full inventory-routing problem.
These distinctions help locate a rich variant within the routing literature
\cite{toth2014vehicle,lahyani2015taxonomy}.

\subsection{Connection to MPVRP-CC}

MPVRP-CC combines capacity limits, repeated vehicle trips, multiple products,
split deliveries, and depot stock availability. It additionally associates a
changeover cost with the succession of products carried by a vehicle.
Consequently, a plan with less travel need not have the lowest total cost.

These ingredients explain its position among rich VRPs. The precise
assumptions, the station--product requests and depot--product supply nodes,
and the mathematical constraints are defined once in
Section~\ref{sec:problem-definition}. The present chapter supplies the concepts
needed to read that definition and the subsequent MILP and CP models.
